# 2026.239.1617 — fix: remove the stray charly submodule; fetch charly at CI time into a temp checkout

## Summary

The candy de-submodule scaffold copied the umbrella structure into every standalone repo, declaring a `charly` git submodule (`path = charly`, `url = https://github.com/opencharly/charly.git`, `branch = main`). The refs downloader's `populateSubmodules` (spec/refs/git.go) initializes EVERY declared submodule on fetch — so a consumer fetching this candy at any ref pulls the ENTIRE opencharly/charly repo into `charly/` inside the fetched tree. That leaked tree breaks the charly parity test (TestFleetCompileParity_PluginRoundTrip): its seedParityProject copies the fetched fixture into .parity/candy/<name>, the .parity root's `discover: candy recursive` walks into .parity/candy/<name>/charly/ finding the ROOT's charly.yml (agentteams box + 663 candy manifests), so cfg.AllBoxNames() returns the root's boxes and the compile resolves "agentteams" instead of the 3 parity fixtures.

**Fix:** remove the submodule gitlink + `.gitmodules`. The CI gate (deploy.yml) keeps validating against the pinned charly by cloning it at CI time into a temp checkout (`/tmp/charly`, pinned tag `v2026.238.1242`) — the candy repo itself no longer carries any charly tree. (Pinned tag replaces the previous floating `branch = main` — a tightening.)
