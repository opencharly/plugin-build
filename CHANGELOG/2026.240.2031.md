# 2026.240.2031 — fix(build): propagate a plugin compile failure as a fatal error, not a warning

## Summary

The build-time plugin connect leg (`buildengine-connect-plugins`) failure was emitted as a warning and the build continued, dying later on `no provider registered` — an error naming the wrong cause. The host leg now returns the error (companion PR opencharly/charly#414); this caller propagates it so the build stops immediately with the actionable message (the plugin name + the go build error).

This is deliberately ALL build-time plugin connect failures — a compile failure, a missing module, or a download error — not only compile failures: the host leg loads only the plugins the build REFERENCES (`collectReferencedPluginWords`), so a connect failure means a plugin the build needs could not be loaded. Continuing would surface the misleading `no provider registered` error.

Fixes opencharly/charly#326.

## How tested

**Committed regression test (B12):** step 4 (the connect leg) is extracted into `connectPluginsOrFatal` so the fatal-vs-warning semantics are unit-testable without faking the loader/scan leg family. `resolve_connect_fatal_test.go` drives it with a fake executor whose `buildengine-connect-plugins` leg fails and asserts done=true with a fatal `BuildResolveReply{Error: ...}` naming the leg and the plugin; a second test asserts a successful connect is NOT fatal (done=false). Verified the failure test FAILS against the pre-fix warning behavior and PASSES with the fix:

```
$ GOWORK=off go test . -run "TestConnectPlugins" -v
=== RUN   TestConnectPluginsFailureIsFatal
--- PASS: TestConnectPluginsFailureIsFatal (0.00s)
=== RUN   TestConnectPluginsSuccessIsNotFatal
--- PASS: TestConnectPluginsSuccessIsNotFatal (0.00s)
PASS

# Reverted to the pre-fix warning behavior (done=false):
--- FAIL: TestConnectPluginsFailureIsFatal
    resolve_connect_fatal_test.go:64: a build-time plugin CONNECT failure must be FATAL (done=true), not a warning the build continues past (#326)
```

**Runtime proof on an explicitly `disposable: true` target** (`check-compile-fatal` in the reproduction project, declared `disposable: true` — never derived from the name). The disposable bed builds the broken-plugin box; its image-build phase triggers the plugin connect. The bed FAILS at image-build (937ms) with the actionable error — the fresh rebuild from the committed tree:

```
$ charly check run check-compile-fatal
charly check run check-compile-fatal: [image-build] START
charly check run check-compile-fatal: [image-build] FAIL after 937ms: exit 1
$ cat .check/check-compile-fatal/2026.240.1850/image-build.log
charly: error: command "build": buildengine-connect-plugins: build-time plugin load failed: plugin "broken-plugin" (source github.com/opencharly/broken-plugin): plugin "broken-plugin": go build in /tmp/pb-repro: exit status 1
               go: go.mod file not found in current directory or any parent directory; see go help modules
```

The build FAILS immediately with the actionable error — ZERO warnings (the warning is replaced by the fatal error). Before the fix, the same reproduction emitted `warning: build-time plugin load: ...` and the build continued to the build steps.

**Module gate:** `go build ./...` clean, `gofmt -l` clean, `GOWORK=off go test ./candy/plugin-build/` passes (full suite green).
