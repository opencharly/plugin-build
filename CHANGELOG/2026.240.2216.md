# 2026.240.2216 — fix(build): warn when the podman store is bloated before a build (#173)

## Summary

Fixes opencharly/charly#173 (overlay-store corruption during `charly box build`). The issue's Arm 3 proved full intra-build serialization (`podman_jobs: 1`) does NOT eliminate the corruption (6/13 runs still failed), which implicates the second measured factor: a massively bloated podman store (3552 images, 132.6GB, 97% reclaimable at filing; the dev host still shows ~106GB reclaimable today).

This change adds a **fail-soft build-time store-bloat warning**: before the podman build loop runs, the drive probes `podman system df --format json` and, when the Images reclaimable bytes exceed 50GiB, prints a warning naming the purge that addresses the factor — `charly clean --deep` (pair with `--invalidate` for the fullest reclaim). The probe runs exactly once per build drive, only for the podman engine, and is fail-soft (a probe failure is skipped silently) — a hygiene nudge, never a build blocker. No sleeps, no retries (R4).

The N-iteration corruption reproduction (the issue's full RCA) remains blocked until the Phase-0 distro sweep lands (the check beds are broken by the candy de-submodule cutover); this lands the defensible mitigation for the store-bloat co-factor now.
