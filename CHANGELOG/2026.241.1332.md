# 2026.241.1332 — perf(build): persistent resolved-project cache + image-cache invalidation

## Summary

- **`resolve_project_word.go`**: `resolveProjectEnvelope` cached persistently (the project load — LoadUnified over the full import closure — was the dominant cost of `charly status`, measured ~4.4s + GC pressure per load, and the status fan-out loads it once per collector). The project changes only on an edit to charly.yml or its imports; the first call after the 5m TTL expires re-fetches with user feedback, every subsequent call reads the cache. The LIVE container state (`podman ps`) is never cached.
- **`drive.go`**: after a box build creates new images, invalidate the persistent image-list cache (`kit.InvalidateImageCache`, from spec#67) so the next status run re-fetches the fresh list.
- **`go.mod`/`go.sum`**: sdk v0.2026241.1311 + spec v0.2026241.1322 (the status-caches tags).
