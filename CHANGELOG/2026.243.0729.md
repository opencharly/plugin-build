# 2026.243.0729 — feat(resolve): collect scan advisories as diagnostics on the validate path

## Summary

The candy scan emits advisories — candy-version skew and local-shadow notes — which went
straight to stderr and never reached any diagnostics envelope. That made them **uncountable**,
so `charly box validate` could not report how many warnings a run produced.

This wires them into diagnostics on the path that needs them:

- **The tolerant resolver** (the validate path) passes `diagWarnSink(&diags)` through
  `spec.ScanSeams.Warn`, turning each advisory into a warning-severity `spec.Diagnostic` that
  flows out in `ValidateProjectReply.Diagnostics`. It is a named function rather than an inline
  closure precisely so the behaviour is testable instead of buried in a call argument.
- **The build paths** pass an explicit named `stderrWarn` sink. They have no diagnostics
  envelope to collect into, so they keep printing — but they say so, rather than relying on a
  `nil` default. Every caller states where its advisories go; there is no implicit behaviour
  to discover later.

## How tested

On the committed tree, against the published tags — no `replace`:

```
$ go build ./... && go test ./...
ok  	github.com/opencharly/plugin-build/candy/plugin-build	0.273s
```

**Three guards on the sinks**, with a negative control:

- advisories are collected as **warning** severity with arguments formatted in
- the sink **appends**, so a multi-advisory run counts the total rather than the last one
- `stderrWarn` really writes to stderr, so the two sinks cannot silently converge

Control — flipping the collected severity to `error`:

```
--- FAIL: TestDiagWarnSinkCollectsAdvisoriesAsWarnings
    item 0 severity = "error", want "warning" — an advisory must never be an error
```

**End to end**, with charly built against all four repos in the chain:

```
$ charly box validate
charly box validate: OK — checked 489 candies, 38 boxes, 29 deploys, 7 distros, 7 builders; 3 warnings, 0 errors
```

Three warnings — two version-skew, one shadow note — counted from diagnostics rather than lost
to stderr. Before this chain the same command printed **nothing at all** on success.
