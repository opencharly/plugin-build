# 2026.266.1755 — feat(build)!: fold the resolved-project cache onto the spec ArtifactStore

## Summary

Migrate `plugin-build`'s resolved-project cache off its bespoke `cache/project.json` map file and onto the shared `spec/cache` **ArtifactStore** (an OCI Image Layout, spec#148) — the SAME content-addressed store `plugin-substrate` and the sdk materialized tree already use (R3: one cache mechanism). This is the `plugin-build` consumer leg of the ArtifactStore cutover.

The merged engine cutover deleted the legacy `cache.Store` API; the old cache here was a hand-rolled `map[key]projectCacheEntry` JSON file with its own oldest-eviction helper. This PR folds it onto the store's own content-addressed layout + bounded prune.

- `resolve_project_word.go`:
  - `projectCacheKey` now returns the named `project` **`*cache.Layout`** + the unchanged content key.
  - `openProjectCacheStore` opens it via `cache.StoreDir("project")` bounded to `projectCacheEntries` (`OpenLayoutLimited`). An unresolvable cache dir yields an inert store.
  - read = `store.Get(key)` + `Entry.Decode`; write = `store.Put(key, cache.Entry{Payload})`.
  - **DELETED** (R5 hard cutover): the `projectCacheFile`/`projectCacheEntry` map shape, its JSON marshal, the atomic tmp+rename file write, and `evictOldestProjectCacheEntries` — the store's own prune reclaims the oldest entry.
  - Fail-closed contract preserved: an empty key (un-enumerable tree) is a guaranteed miss, and a write is a no-op.
- `resolve_project_cache_test.go`: round-trip / no-TTL / scope / fail-closed / eviction tests rewritten onto the ArtifactStore API; the eviction test now proves `OpenLayoutLimited`'s own prune.
- `test_main_test.go` (new): isolate the CONFIG STACK for the package, **matching the sdk's own `loaderkit/test_main_test.go`**. `LoadUnified` layers the real `/etc/charly/charly.yml` as the SYSTEM layer; without this a host shipping a system config yields a non-empty stack for even a project-less temp dir, so `resolveProjectEnvelope` legitimately dials the `loader-bootstrap` HostBuild leg — which the nil-executor empty-project contract test relies on never happening.
- `go.mod`: re-pin `sdk v0.2026266.1111` + `spec v0.2026266.1306` (the merged ArtifactStore cutover). The same bump carries the transitive churn the new pins require: `golang.org/x/sync` `v0.20.0 → v0.22.0`, plus `github.com/opencontainers/go-digest v1.0.0` and `github.com/opencontainers/image-spec v1.1.1` added as indirect requires (the OCI types `spec/cache` imports), and the `golang.org/x/{net,sys,term,text}` indirect bumps those pull in.

**Breaking change:** the on-disk cache shape is now an OCI Image Layout; the legacy `cache/project.json` is no longer read (an immediate miss re-resolves).

### Review round 1 — fixed (append-only commit `c6e5ef7`)

- **R4/test isolation:** `TestProjectCacheKeyFailsClosedOnUnreadableManifest` now sets its own `CHARLY_CACHE_DIR` (`t.TempDir()`) like its three sibling store tests. Previously `projectCacheKey` resolved the operator's ambient `project` store, so `store.Len() != 0` counted whatever that store already held and failed on any host that had run plugin-build. Proven fail-without-fix: against a populated ambient store the un-isolated test fails `len=1`; isolated it passes.
- **R5:** swept the stale TTL claim in the cache comment above the resolve call (the resolved-project cache has NO time validity — the key is a content address).

### Review round 2 — fixed (append-only commit `631e051`)

- **R1:** corrected the `projectCacheKey` doc added by this PR. It claimed an inert store "yields an empty key"; the code returns the computed content key for an enumerable tree — an inert store skips caching only because its `Get` misses and its `Put` no-ops. The empty key is reserved for the un-enumerable-tree fail-closed path. Reworded to the real mechanism.
