# 2026.269.0606 — fix: invoke the validation gate by its full capability identity

## Summary

The pre-build validation gate is the **nested** command capability `command:validate:box`
(`charly box validate`). A nested command is never reachable by its bare word — once charly
makes the parent part of the capability identity, the provider registry keys it at
`command:<word>:<parent>` — so the peer dispatch must name the parent, exactly as the CLI
grammar does.

`validateProjectLeg` now passes `CommandParent: "box"` on its `InvokeProvider` call.

Without this the leg resolves nothing after charly's identity change;
`sdk.InvokeProviderOpts` gains the `CommandParent` field for exactly this.

Pins: sdk → merged `v0.2026269.145`; spec → merged `v0.2026269.138` (a required transitive
of the sdk bump); the CI candy-gate pin → charly `v2026.269.0556` (whose adopted spec
grammar accepts the three-segment form), with the repo project's `version:` stamp migrated
to that binary's schema head.
