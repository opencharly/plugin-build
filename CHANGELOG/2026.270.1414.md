# 2026.270.1414 — fix(build): drop the removed deploykit.ComputeEffectiveVersions call

## Summary

`plugin-build` (a compiled-in module) fails to compile against the merged post-C7 + post-schema-versioning `sdk`/`spec`:

```
./resolve.go:154:22: undefined: deploykit.ComputeEffectiveVersions
```

`sdk#313` (`sdk v0.2026270.1147`) deleted `deploykit.ComputeEffectiveVersions` and drops the `ai.opencharly.version` OCI label entirely — images are identified by `ai.opencharly.box`. The spec analogously removed `Version` from `spec.ResolvedBox` / `spec.ResolvedBoxView` / `spec.ResolvedProject` (`spec v0.2026270.938`).

This PR:

1. **Drops the `deploykit.ComputeEffectiveVersions(resolved, layers)` call** in `resolve.go` (the version label is gone; no version label is reintroduced).
2. **Documents the consequence** at the removal site: the deleted call was the sole writer of `ResolvedBox.EffectiveVersion` on the resolve path; the field is intentionally left unset and nothing in `plugin-build` reads it.
3. **Adds coverage that fails if the changed behaviour is wrong**, in two anchored halves:
   - `TestResolveBuildEngine_DoesNotPopulateEffectiveVersion` — parses `resolve.go` and asserts the **changed function** `resolveBuildEngine` neither calls `ComputeEffectiveVersions` nor assigns any `.EffectiveVersion` field. This is anchored on the edited function itself, so it fails if the removed population step is re-introduced at the plugin-owned call site.
   - `TestResolvePipeline_LeavesEffectiveVersionUnset` — drives the runtime chain that function still runs (`ResolveAllBox → ComputeIntermediates → GlobalCandyOrder`) over a fixture box and asserts `EffectiveVersion` stays empty.
   Neither uses the hardcoded `fullResolvedBoxFixture`/golden (those set `EffectiveVersion` only for wire-projection completeness and say nothing about the resolve path).
4. **Sweeps the now-stale comments** (R1/R5): the "`ai.opencharly.version` OCI label host-side" note in `podman.go` is corrected; remaining mentions of the deleted symbol are explanatory only (see the sweep output below).
5. **Adapts the two tests + golden** that referenced the removed `Version` fields; the regenerated `testdata/resolved_project_golden.json` drops exactly the two `version` keys and keeps `effective_version`.
6. **Bumps the module requires** to `sdk v0.2026270.1147` + `spec v0.2026270.938`.

This is the `plugin-build` half of the C7-adoption cross-leg flag on sdk#313, carried forward from the auto-closed #18 (cross-referenced there). Relates to opencharly/plugin-service#7.
