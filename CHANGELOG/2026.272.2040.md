# 2026.272.2040 — fix(plugin-build): adopt the #717 consumer change — leveled scan diagnostics (Warn→Diag)

## Summary

`sdk#288` (`v0.2026271.915`) added a `context.Context` parameter to the `deploykit`
deploy-config family, which is the fan-out this wave exists for. **`plugin-build` is
unaffected by it** — and that is a **divergence from issue #738's premise**, reported here
per R1.

> **⚠️ DIVERGENCE (R1, reported).** Issue #738 lists `plugin-build` among the plugins that
> "each call the ctx-changed `deploykit` functions … with the OLD arity." **That is not the
> case.** `plugin-build` has **ZERO ctx-family call sites** (`grep` for
> `deploykit.ResolveContainer` / `ResolveBoxEngineForDeploy` / `SaveDeployConfig` / … returns
> nothing). `go build ./...` at `sdk v0.2026272.1813` fails **only** on the coupled `spec#186`
> change: `unknown field Warn in struct literal of type loaderkit.ScanSeams`.

The real, coupled blocker is the **required `spec` bump** (`v0.2026270.938` →
`v0.2026272.1512`, carrying `spec#186` = *"per-box candy-version scope + leveled diagnostics"*,
merged alongside `sdk#324` as the `#717` root fix). It renames the scan seam and levels its
diagnostics:

```
spec.ScanSeams.Warn func(format string, args ...any)
  → spec.ScanSeams.Diag func(level spec.DiagLevel, format string, args ...any)
```

`spec#186` also introduces the CLOSED severity vocabulary (`SeverityInfo` / `SeverityWarning` /
`SeverityError`) and `Diagnostic.IsError()` (fail-closed). The semantics matter: a bare ref
pinned at incoherent tags **resolves** (newest referenced tag wins) and is now reported at
`DiagInfo`, so it must **not** be counted as a gate-failing warning. That is exactly what makes
`#717`'s acceptance (`errors: 0, warnings: 0`) reachable. This is a **blocking** member of the
same cutover per R2 — not a deferrable unrelated change.

### Changes

| File | Change |
|---|---|
| `resolve_legs.go` | `diagWarnSink` → `func(spec.DiagLevel, string, ...any)`; routes each level through a new `diagSeverity` helper (`DiagWarning` → `SeverityWarning`, everything else → `SeverityInfo`) |
| `resolve_legs.go` | `stderrWarn` → level-aware, prefixing `Warning:` / `Notice:` (mirrors `loaderkit.emitDiag`'s own nil-sink fallback) |
| `resolve_legs.go` | `scanSeamsLeg` / `namespaceScanSeams`: field `Warn:` → `Diag:`; param `warn func(string, ...any)` → `diag func(spec.DiagLevel, string, ...any)` |
| `resolve_legs.go` | `validateProjectLeg`: raw `it.Severity == "warning"` → `!it.IsError()` (with a new INFO tier, "not warning" would wrongly count INFO as an error) |
| `resolve_project_tolerant.go` | local `diagSeverityError` raw `"error"` literal → `spec.SeverityError` (one string domain, spec#186) |
