# 2026.280.0647 — fix(build): wire --no-cache to the engine (bypass the local layer cache) (#483)

## Summary

`charly box build --no-cache` was **read** — but only enough to skip the `--cache-from` EXPORT; the LOCAL layer cache still served. opencharly/charly#483 measured `126/136` layers served from cache on a build the operator asked to be cold, and `charly check run` reported it as a PASS.

Re-derivation (the issue's grep covered `charly/`, `sdk/`, `spec/spec/` but not the plugin repos): `candy/plugin-build/drive.go:73` copies `req.NoCache` into `driveConfig.NoCache`, and `podman.go`'s `cacheArgs` reads it — returning `nil`. So the flag is not dead; it just does less than its help ("Disable build cache entirely") says.

Fix: a no-cache build returns the **engine's own `--no-cache`**, so the local layer cache is bypassed too. `--cache none` is the same "do not use the cache" and takes the same path.

Scope, stated honestly: this does **not** defeat a `--mount=type=cache` package mount (a pacman/dnf package cache survives `--no-cache` by design) — the flag means "cold **layer** cache", which is what its help says. The issue names that mount as a separate question; it is not silently implied here.

Closes opencharly/charly#483 (lands in `charly` on the next plugin-build pin bump).
