# 2026.282.1933 — fix(plugin-build): adopt the path-scoped namespace-ancestor seam — a global cycle guard drops the second path (sdk#353)

## Summary

`opencharly/sdk#353` replaced four re-derived per-function cycle guards with **one shared, path-scoped** ancestor stack (`loaderkit.NamespaceAncestors`) and changed the exported `ResolveProjectSeams.FillNamespacedBoxes` signature with it. This plugin is the **only** implementor of that leg — swept org-wide — and it did not follow. It now does, and this PR is the consumer half of that cutover.

**The old shape was not equivalent, and the difference is silent.** `fillNamespacedBoxes` carried its own `visited map[*spec.UnifiedFile]bool` — a **global** set. The loader deliberately mounts the SAME `*spec.UnifiedFile` at more than one namespace path (a diamond import, a multi-alias mount), so the first descent marked that pointer and **every later alias was dropped**: the resolve quietly returned fewer boxes than the project declares, while the cycle the guard exists to stop still terminated. That is why the bug is invisible to any test that only exercises a cycle.

**So this is not a type rename.** Adopting the seam means `Enter` on the way in and the returned `leave` deferred on the way out, so the guard is scoped to the current descent path.

**`spec` moves too, and that is minimum-version selection rather than a second decision.** The diff also carries `github.com/opencharly/spec v0.2026273.203 → v0.2026280.2244`. **`sdk v0.2026282.1759` itself requires `spec v0.2026280.2244`**, so the bump raises it the moment the `sdk` pin moves — every file in the diff is accounted for by the one intended change:

```console

+	github.com/opencharly/sdk v0.2026282.1759
```

**The `sdk` pin moves with it:** `v0.2026276.48` → `v0.2026282.1759`, the tag that carries the seam. Without the bump the new signature is not even visible, which is why the two halves belong in one commit rather than a "bump later".
