## Summary

**The drive itself. `build:box` no longer shells out to an engine at all.**

The Containerfile is built by the `buildkitdrive` kit — daemon ensure with the resolved `stage_parallelism`, the `buildctl` invocation, and the store bridge — and every built image is **bridged into the RUN engine's store**, because that is where every later read of it lives: its capability labels, its deploy, its status, its inline merge, `charly clean`.

**DELETED with the drivers, in this same commit (R5):**

| deleted | why |
|---|---|
| `podman.go` (253 lines) | `{podman\|docker} build --layers=true -f -`, `docker buildx build --push`, `podman build --manifest`, the cache-arg matrix, the manifest inspect, and the **retry sleep ladder** |
| `podman_test.go` (353 lines) | its argv matrix — **exactly** the unvalidated engine×flag surface `plugin-build#29` recorded. Every cell belonged to a driver that is gone, so the issue closes **by deletion**: no validation, no shim |
| the cross-engine transfer in `ensure.go` | the two-store split was its only reason to exist, and the bridge is what closed the split |

plus every surviving mention of the driver in `charly.yml`, `README.md`, `AGENTS.md`, `bootstrap.go`, `drive.go` and `host_prep.go` — swept claim-keyed, with the only remaining hits being comments whose subject *is* the deletion.

**⚑ THE BRIDGE'S NAMED DUTY, proven live rather than asserted.** A load returns success while landing an OCI-exported image **UNTAGGED** — measured here directly (`podman load` on this export leaves the ref unresolvable: `Error: … image not known`) — so the kit's `LoadExport` performs load, tag, then **verify**, and this leg's live test asserts both halves of what the duty is for:

```
$ go test -count=1 -v . -run TestBuildImage_Live
--- PASS: TestBuildImage_LiveBuildsAndBridgesIntoTheRunEngine (1.46s)
```

It builds a real Containerfile (`FROM alpine:3.20` + a LABEL) through a real daemon and `buildctl`, and then asserts (a) the image **resolves by its CalVer ref** in the run engine's store — the tag duty — and (b) its **label reads back through that engine** (`container.InspectLabels`), which shares no store with the builder. That second assertion is the reason the bridge exists at all.

**⚑ Mutation-proven — and the first attempt taught me a rule.** Neutralising the tag step makes the live test fail with `the loaded image is not resolvable as localhost/leg4-live:2026.287.1200 … image not known`. **My first attempt at that proof was invalid**: I mutated the *sdk worktree* while the plugin compiles against the **pinned** module, so the mutation never applied and the test passed — a green result that proved nothing. Redone through a workspace that substitutes the local sdk, it fails as above; restored with the pre/post sha256 compared (`IDENTICAL`). **A mutation must run against the tree the test actually compiles** — a mutation that never applies reads exactly like a mutation that cannot fail.

**⚑ TWO DECISIONS:**
1. **PUSH stays one path and keeps every semantic.** `buildctl` takes **multiple `--output` flags** (its own help, measured), so a `--push` build emits `type=image,name=<tag>,push=true` **and** the OCI export: BuildKit's image exporter replaces both `buildx` and `podman manifest push` — and is the only path that can push the multi-platform image — while the local load keeps the **inline merge** and the label reads working. The kit stays push-policy-blind; the drive composes the registry destination (`pushOutput`), pinned in both directions by a test that also asserts the OCI export is emitted **exactly once** (a duplication I introduced and caught while writing it).
2. **`EngineName` now MEANS the run engine** (`rt.RunEngine`) — **a change of meaning, not of name only** — and deliberately without a wire change: all three surviving consumers (the privileged builder bootstrap, the inline merge, the bridge's engine binary) want exactly the run engine.

Changed: **17 files, +390/−685**, and the accounting is a sum: **3 added** (`buildkit.go`, `buildkit_test.go`, `buildkit_live_test.go`) **+ 2 deleted** (`podman.go`, `podman_test.go`) **+ 12 modified** = 17. One commit. A **net deletion of ~295 lines** is the shape of this cutover: fewer paths, one builder.
