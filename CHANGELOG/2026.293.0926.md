# 2026.293.0926 — feat(build): honour the drive's single host platform when solving a local build

## Summary

Honours the drive's host-resolved single platform when solving a **local** build.

`box.Platforms` comes from `cfg.Defaults.Platforms` / `img.Platforms`. When a project declares no platforms, the base image's multi-arch manifest list expands into one build **per architecture** — so a local build of a box based on `quay.io/fedora/fedora:43` built both `linux/amd64` and `linux/arm64` for an image only ever run on this host.

`driveConfig.Platform` already exists and is documented as *"target platform (host-resolved; empty on a push build)"*. It was simply never consulted at the solve. This makes it authoritative:

```go
- Platforms:     box.Platforms,
+ Platforms:     buildPlatforms(c.Platform, box.Platforms),
```

**Why no default changes.** A push build keeps `Platform == ""`, so it keeps the full declared/multi-arch list unchanged. Only a local build — the case that has a host-resolved single target — narrows.

The failure this fixes is not theoretical:

```
$ sudo dmesg | grep -i 'Killed process .*charly'
Out of memory: Killed process 3301335 (charly) total-vm:8453256kB, anon-rss:5918972kB
```

`charly` was OOM-killed at 5.9 GiB buffering two buildkit streams, the second existing only because the base image is multi-arch.

The diff is **52 insertions and 1 deletion**, across `candy/plugin-build/buildkit.go` (the narrowing) and `candy/plugin-build/buildkit_platforms_test.go` (the coverage).
