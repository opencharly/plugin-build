# 2026.305.2204 — feat(build): ensure an image's BASE before BuildKit resolves it (charly#949)

## Summary

A `charly box build` whose base image cannot be FETCHED fails hard, and nothing interposes to BUILD that base locally (opencharly/charly#949 — the operator's directive: *"charly should always fall back to building images locally if they can't be fetched from the registry"*).

The base is a build ARG that BuildKit resolves **inside** `buildctl` (`ARG BASE_IMAGE=` + `FROM ${BASE_IMAGE}`, `sdk/deploykit/generate.go`), so a base that is not where the build looks for it dies deep inside the build with the registry's own error. Three parts, in `candy/plugin-build/`:

1. **`drive.go` — `driveConfig.Ex *sdk.Executor`** plus `Ex: ex` at its one construction site. The drive resolved and built plugin-side but held no executor, and the ensure contract takes one.
2. **`buildkit.go` — `baseImageRef`** reads the base ref out of the Containerfile the drive itself just wrote, so no new field has to carry it across the resolve/build boundary.
3. **`buildkit.go` — `ensureBaseImage`**, called in the window between the daemon `Ensure` and the `buildctl` run: nothing to do for `scratch` or a missing ARG; a no-op when the base is already in the run engine's store (`kit.LocalImageExists`); otherwise the SAME ensure contract `build:ensure` owns (resolve against the project's `charly.yml` → pull → build locally). A failure **names the base ref**, says it could not be fetched, and says no local build was possible — instead of a token-fetch status the reader cannot act on.

**Round 2 review fixes, in this head.** The decision is now proven in-tree rather than deferred:

- **`ensureBase` is a seam** — the ensure contract as a package-level function variable, assigned in `init()` because the contract reaches back into this drive (`ensureRemoteRef → runBoxBuild → buildImage → ensureBaseImage → ensureBase`), which a var initializer turns into an initialization cycle the compiler refuses.
- **`TestEnsureBaseImage_RoutesAMissingBaseThroughTheEnsureContract`** pins the resolving arm's decision: a base that is not local, on a drive that **does** hold an executor, must reach the contract with the Containerfile's ref, the drive's `Dir` and the drive's `RunEngine`; a contract failure must fail the build and name the artifact, the failed fetch and the missing fallback. On the pre-change shape the base is silently left unfetched and BuildKit dies with the registry's own auth error — the defect this PR is about.
- **`TestEnsureBaseSeamIsWired`** asserts the `init()` wiring, because a nil seam would panic every cold build.
- The venue-specific end-to-end — a credential-less host whose project carries the base's recipe, so the fallback actually BUILDS it — remains **opencharly/plugin-build#43** under `## Filed issues`: the decision and its message are proven here; that run needs a venue this repo's gate cannot construct.

**Re-cut onto current `origin/main`, keeping both sides.** The original branch tip (`3452b6b`) was **10 commits behind** and main had since moved the very files this change touches (`buildkit.go`: the image store, annotated exports, the platform solve; `drive.go`: `RegistryMirror`), so the change was re-applied on a fresh branch off `origin/main` (`3c2edf6`), nothing was force-pushed, and the old branch is untouched. The resolution keeps **both** config fields and adapts the one call whose signature moved:

```go
// main since this branch was cut:
RegistryMirror   string // local charly OCI registry mirrored for ghcr.io/opencharly
// this change:
Ex *sdk.Executor

// adapted from the branch's 4-argument call to main's 5-argument contract, now crossed via the seam:
if err := ensureBase(ctx, c.Ex, ref, c.Dir, c.RunEngine); err != nil {
```

**This is the ENSURE half — and main now carries the other half it needed.** The drive's daemon options set `DaemonOptions.RegistryMirror`, mapping `ghcr.io/opencharly` to the local charly registry, so a base that was **built** is resolvable by `buildctl` instead of being fetched upstream, and a base this drive builds through the ensure contract is pushed to that same registry by the same drive. The original author measured that a base present only in the *run engine's* store did **not** satisfy BuildKit — precisely the gap the mirror closes. The two halves are complementary, not alternatives.
