## Summary

`charly box build <box> --tag <tag> --push` resolved the requested box **and every transitive base**, then appended BuildKit's registry exporter to every one of them. When a base came from an `import:` namespace (`crabbox.pod-crabbox`, the CachyOS `arch` under it), the drive built it locally under the current tag and tried to push it with the importing repo's `GITHUB_TOKEN`. That token carries `packages: write` for the importing repo's package only, so the foreign push was denied and the build failed before the requested image existed:

```
#8 ERROR: failed to push ghcr.io/opencharly/arch:2026.308.1917: denied: permission_denied: write_package
```

Measured on `pod-crabbox-systemd`, `image` run `41895678841` (`completed/failure`); every one of the eleven `pod-crabbox-*` variant repos inherits the failure.

The exclusion is **foreign package ownership**, not "was this box requested". This change makes `--push` publish:

- every explicitly requested box (an explicit request still attempts its push, so a foreign request fails loudly rather than being silently skipped);
- every box in the build order that is **not namespace-qualified** — this project's authored dependencies AND its auto-intermediates. An unqualified box is this project's own: its push creates or writes a package this repo's workflow owns.

Only boxes qualified by an `import:` namespace stay excluded. A full build (`--push` with no positional box) publishes every unqualified box it built. The local charly OCI registry mirror push is unchanged. A failure to push the requested box is unchanged and still aborts the build: the error is not weakened.

The decision is `pushTargets` in `candy/plugin-build/buildkit.go`, applied by `pushOutputFor` at the argv seam; `driveConfig` carries the target set, populated from the build request and the resolved reply. The namespace predicate is derived from `spec.SplitNamespaceRef`, the one definition of the namespace grammar.
