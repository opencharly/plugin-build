### RCA — the missed control (round 3)

The previous round named a doc comment attached to the wrong declaration in the TEST file. I fixed
that instance, re-ran the same gate that had missed it, and pushed — and the same defect was still
present in the production file. Two misses, named:

1. **The gate is blind to this class by construction.** The pre-push gate here is `gofmt -l` +
   `go vet` + `go build` + `go test`. None of them models comment-to-declaration attachment: gofmt
   preserves comments wherever they sit, `go vet` has no such analyzer, and this repo runs no linter.
   Running the same gate a second time therefore could not catch the recurrence — the control I used
   had no coverage of the property I claimed to have fixed.
2. **The fix was instance-scoped, not class-scoped.** The defect is a CLASS — "a comment block that
   merged across declarations" — and I repaired only the instance I was shown. The production file
   carried the identical shape because the insertion point was the same (my helper landed between
   `containerfileBaseRef`'s doc comment and its function), which a one-line sweep of every file the
   diff touched would have shown.

**Root fix in this head:** the region was rewritten so each of the three helpers carries its own
comment immediately above its own declaration, ordered `containerfileStageRefs` →
`containerfileFromRefs` → `containerfileBaseRef`, each separated by a blank line. The sweep is now
explicit and repeatable: `grep -n '^func containerfile' -A1` lists three definitions, each preceded
by its own block.

**A durable control** would be a `go/doc`-based check (for every exported/unexported func, the
doc `go/doc` associates with it must exist and must not name a different symbol); this repo does not
run one today, and adding a linter is its own change, so it is recorded here rather than smuggled
into this fix. Until then the class is covered by review, and this RCA is the record of why.
