# 2026.319.1655 — fix(validate): count the init-dependency warning instead of printing it into the void

## Summary

`charly box validate` printed the init-dependency warning and then reported **`0 warnings`** — the number a reader and
a landing gate take as the verdict. This PR makes the printed warning and the counted warning the same event.

```
warning: box "demo-box" resolves init "supervisord", which depends on the "supervisord" candy, but that candy is
         not in this project's scanned set — …
charly box validate: OK — checked 1 candy, 6 distros, 7 builders; 1 warning, 0 errors
                                         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

### The measured mechanism (opencharly/sdk#519)

| step | finding |
|---|---|
| who emits it | `deploykit.InjectInitDependsCandy`, reached from `loaderkit.ProjectResolvedProject`, called by this package's `resolve_project_tolerant.go` |
| in which process | **the host's**, because `candy/plugin-build` is COMPILED INTO the charly binary — named by a rebuilt binary whose SDK reporter prints its pid: `INJECT-EMITTER pid=<host pid> box=demo-box` |
| why four earlier placements failed | they sat in other processes, and — the harder lesson — every `CHARLY_REPO_OVERRIDE` test of them measured a binary that does not contain this code at all |
| why the count was 0 | the reply had no diagnostics field until **opencharly/spec#330** added one |

### The fix

`resolve_project_tolerant.go` installs `initDependsCollector` for the duration of the validate resolve; the warning
rides `spec.BuildResolveReply.diagnostics` into the summary that counts it.

### The two dependency bumps this PR carries, and why

| module | from → to | why it must move |
|---|---|---|
| `github.com/opencharly/spec` | `v0.2026296.1036` → `v0.2026319.1619` | this is where `BuildResolveReply.diagnostics` exists — **opencharly/spec#330**, without which there is nowhere to put the finding |
| `github.com/opencharly/sdk` | `v0.2026305.2312` → `v0.2026319.1629` | the release carrying the reporter seam (`SetUnsatisfiedInitDependsReporter`) **and** the new spec pin — **opencharly/sdk#530** |

Both are producer-first: spec#330 merged and tagged `v0.2026319.1619`, then sdk#530 advanced its own spec pin and was
tagged `v0.2026319.1629`. Three indirect deps follow from the sdk bump (`cuelabs.dev/go/oci/ociregistry`,
`github.com/rogpeppe/go-internal`, `golang.org/x/oauth2`).

**The collector RECORDS and does not print.** The host's own project resolve already prints this line for the same
command, so a printing collector showed it twice — measured on the fixture as *two prints, one count*. `TestInitDependsCollector_RecordsWithoutPrinting`
fails if the print returns.

## The diff is now exactly what this Summary describes

Round 2 caught a real discrepancy: the previous commit's message said "without the build-path change" while its diff
still carried it, because `git checkout -- resolve.go` restored the **committed** version rather than `origin/main`'s.
The revert is explicit now, and the whole diff is:

```console
$ git diff origin/main --stat
```

**Concurrency is stated, not left implicit** (the review asked): the reporter seam is a process-global and this plugin
is compiled into the host binary, so the exposure is one resolve per invocation. A real guard needs a per-invocation
reporter in the SDK, recorded on opencharly/sdk#519 rather than improvised with a mutex around a global that other
callers also mutate.

## Change classification

Behaviour change in one direction: a warning that was invisible to the count is counted. Nothing that passed
validation now fails — the diagnostic is warning severity, and `1 warning` is exactly what the operator already saw
printed.

**Breaking change + rollback:** none — no existing field or command changes shape; a project with no unsatisfied init
dependency reports exactly as before (`0 warnings`, pasted above). Rollback is the single commit.
