# 2026.322.2319 — fix(build)!: a caller's --tag must not rename borrowed builder nodes

## Summary

One build RESOLVE stamped **one** tag on **every** box it touched. `charly check run
check-comfyui-pod` runs

```
charly box build comfyui-cdi --tag check-comfyui-pod-2026.322.1943
```

and `resolveBuildEngine` threaded `req.Tag` through `buildkit.ResolveAllBox`, the namespace walk,
and `deploykit.ComputeIntermediates` — so `arch-builder`, a builder borrowed from the `arch`
distro namespace, was stamped too, and the emitted Containerfile's builder stage then named

```
ghcr.io/opencharly/arch-builder:check-comfyui-pod-2026.322.1943
```

a ref no registry serves:

```
error: failed to solve: ghcr.io/opencharly/arch-builder:check-comfyui-pod-2026.322.1943:
  failed to resolve source metadata: ... not found
```

The comment that wrote this down said *"so every box view is stamped with the SAME tag"* — that
sentence is the defect (opencharly/charly#1208, traced there to the line).

This is a contract violation, not just a bad ref: **DESIGN.md D-KIND-2** makes a builder a
vocabulary node owned by the repository that declares it, so a caller's `--tag` has no business
renaming another repository's node, and the tag it then asks a registry for is one the owning repo
never published.

### The fix — the two tag roles the resolve always had

`candy/plugin-build/build_tag_scope.go` (new) owns the rule:

- **`borrowedTag`** — `buildkit.ComputeCalVer()`, computed **once** for the whole resolve (it is
  clock-derived; computing it twice would diverge across a clock tick — the existing comment's
  concern, preserved). Every box the build does **not produce** keeps it: a builder node, and any
  auto-intermediate off a target's own chain.
- **`targetTag`** — the caller's `req.Tag`, stamped on exactly the boxes the build **produces**:
  the targets the request names and their transitive dependency chain, or every box for a full
  build (the CLI's `"" → all enabled`). This stays load-bearing — `charly check run` builds the bed
  image with the run's tag and verifies the artifact **by** that tag
  (opencharly/plugin-check#115). A fix that merely dropped the override would break the bed's
  freshness proof instead.

Everything is resolved at `borrowedTag` and the output set is **then promoted**, so borrowed nodes
stay untouched by construction rather than by a second guess at what each one is. With no
`--tag` the two roles collapse onto the one CalVer a bare build has always used (byte-identical
behaviour).

`builderNodeNames` collects the builder set from the **consumer's reference** — every box named by
some box's effective `builder:` map, plus each `from: builder:` box's `BootstrapBuilderImage` — and
a builder is excluded **even when this build rebuilds it**: its identity is its owner's, and the
drive then resolves it under the tag it was built with. The one exception is a request that
**names** the builder as its target (`charly box build <builder> --tag <t>`): that node is then the
build's artefact, so the override applies to it and to its base chain. `retagBox` moves `Tag` **and**
`FullTag` together, because `FullTag` is what the emitted `FROM`/`COPY` names.

## Change classification

- **Class:** build-drive resolve behaviour (plugin library), consumer-visible in the tags of the
  images a build produces.
- **Breaking change + rollback:** yes — and narrow: **only builder nodes change tag.** For a
  **filtered** build (`charly box build <box> --tag <t>`), the named target **and its transitive
  dependency chain** carry `<t>` exactly as they do on `main` — `produced` is the filtered order and
  `stampBuildOutput` retags every produced non-builder, which is what
  `TestBuildTagScope_BorrowedNodesKeepTheirOwnersTag` asserts (`app`, `arch`, `arch-a` →
  `<t>`). What breaks is the builder node: it keeps the CalVer its owning repo gave it instead of
  being renamed to `<t>`, which is the defect this PR removes. Boxes outside the build's output
  (sibling groups, borrowed vocabulary) likewise keep the resolve's CalVer; for a filtered build
  that difference is visible only in the projected envelope, never in a Containerfile this build
  emits. Round 2 adds no breakage of its own, and one behaviour change worth naming: for a
  **tagged** build an out-of-tree reader of `deploykit.Generator.Tag` now sees the resolve's
  CalVer where `main` wrote `req.Tag` — disclosed, with the grep that shows nothing in-tree reads
  it, and the field is populated rather than emptied. Rollback: revert the squash
  commit; `main` then returns to stamping one tag on every box, and the affected beds go back to
  the registry miss in opencharly/charly#1208. Nothing in the wire shape, schema or CLI changes —
  no field added, no command removed, and `charly box generate`/`build` keep their flags.
