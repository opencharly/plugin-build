# 2026.325.0905 — fix(ensure): pull an external base as written, and never build a box as its own base

## Summary

Fixes opencharly/plugin-build#61. From clean local storage, every debian- and ubuntu-family box deadlocked on its own image lock: `charly box build debian` (`base: debian:13`) and `charly box build ubuntu` (`base: ubuntu:26.04`) waited the full 30m on a lock that the same process held, then gave up. There were two defects in `candy/plugin-build/ensure.go`, and each is fixed at its source:

1. **An external base was never pulled.** `resolveImageRefPlugin` returned `""` for a ref that is neither a project box key nor a "full ref" (`LooksLikeFullRef` requires a slash), so the pull branch was skipped entirely. Now a ref that is not a box of this project is an external image, pulled **as written**; the engine normalizes `debian:13`.
2. **A ref was mapped onto a box by leaf name alone.** `buildableShortNamePlugin` turned Docker Hub's `debian:13` into the project box `debian`, which is the box being built. Now a ref maps onto a box only when it **names** that box: its bare key, or the box's own published repository (registry/name, computed from the config with no local-store probe). `ghcr.io/opencharly/fedora:<calver>` still builds `fedora`.

Plus the invariant, stated where the build would start: the ensure path for a box's **base** carries that box (`self`), and `selfBaseError` refuses a fallback onto that same box with a clear error instead of a self-wait. This also holds for a registry-less project, where rule 2 alone cannot tell `debian:13` from `debian`. The `build:ensure` word passes no `self`, so its behaviour is unchanged.
