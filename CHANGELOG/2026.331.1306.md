# 2026.331.1306 — feat(build): reuse an unchanged build's ref instead of minting a new CalVer

## Summary

Fixes the mechanism in opencharly/charly#1292 after reproducing it: every box build minted a **fresh CalVer ref per invocation**, so a repeated build of an unchanged tree moved the `FROM`/`ARG BASE_IMAGE` refs and the build summary never named them.

The corrected RCA (measured, recorded on the issue): **a changed tag with an unchanged digest is a BuildKit cache HIT**, so tag churn alone does not invalidate layers. What actually re-runs is the build itself, and the floating `pacman -Syu` / `releases/latest` steps then change the bytes. This PR addresses the ref half:

- **Option B — decide the ref AFTER the build.** The drive reads the archive's image ID (`buildkitdrive.ImageID`) and compares it with the **newest local ref of the same repository**. Same artifact + present in the charly store → **reuse that ref** (nothing to annotate, store or import); changed artifact → mint a fresh CalVer. The predicate is the artifact's content address, never the clock.
- **No same-minute overwrite.** `mintAutoRef` returns the bare CalVer when the minute is free, a numeric suffix (`-2`, `-3`) when a DIFFERENT artifact already owns it, the same ref when it already names this artifact, and a content suffix only when every numeric slot is taken. `isAutoTag` accepts the suffix, so a bumped tag is still recognised as the drive's own. Without this, two changed builds inside one minute re-pointed one tag at different bytes — the exact harm the predicate exists to prevent (measured below).
- **Children follow the published refs.** A child's Containerfile is rewritten with the refs the drive actually published, so its `ARG BASE_IMAGE` / builder `FROM` names a real artifact (token-bounded, so `:probe-1` cannot corrupt `:probe-12`).
- **The summary names the refs.** `--- Building <box> (base <ref>; builders <refs>) ---` then `--- <box> -> <ref> (reused|built; image <id>; previous <ref>) ---`.
- **Coverage.** `ref_reuse_test.go` pins the decision table, the collision bump, the tag grammar and the substitution boundary.
- **The comments describe the bump.** `ref_reuse.go`'s header and the `buildImage` note said a changed artifact mints a fresh CalVer — true before `mintAutoRef`, incomplete after it. Both now name the minute bump, so the file describes the code (R5).
- `candy/plugin-build/buildkit_tail_test.go` is an **import-grouping fix only** (no behaviour change): it restores `gofmt` on a file `main` left unsorted, found by the package gate.

Scope: a **caller tag** (any non-CalVer tag — a bed tag like `check-tmux-pod-2026.331.1225`, a release/user tag) names the artifact and is kept; a **push target** (its ref is in the buildctl argv) and a **mirrored build** keep the resolve-time ref; a **direct `buildImage` caller** keeps the ref it passed.

The 100 GB BuildKit GC budget (the other half of the cache story) is in opencharly/sdk#650; the `defaults.buildkit` surface is opencharly/spec#447 (merged) + the plugin-build daemon-config branch. This PR is independent of both.

### Spike

**RCA claim:** the per-build ref churn is real, but a tag change alone does not invalidate the cache; the artifact's content address is what must govern the ref.

**Candidates, each with its instrument and pasted output:**

- **A. Keep minting (status quo).** Instrument: two builds of the same unchanged probe seconds apart, with the pre-change decision. Two defects, both pasted:
  ```
  # a changed artifact re-pointing an existing tag at different bytes (same minute):
  build 1: testbase -> ghcr.io/opencharly/testbase:2026.331.1204 (built; image sha256:2289e7b3...; previous ...:1157)
  build 2: testbase -> ghcr.io/opencharly/testbase:2026.331.1204 (built; image sha256:4a96c580...; previous ...:1204)
  ```
  The second build wrote a DIFFERENT artifact onto the tag the first had just published, and a fresh tag on every invocation. **Fails** the issue's ask.
- **B. Decide the ref after the build from the artifact's image ID; reuse the newest same-repo ref when it is the same artifact, else mint (with the minute bump).** Instrument: the same probe rebuilt twice, plus the two `check-tmux-box` builds above. Result: `reused` on every repeat, no mint, the child's base rewritten. **Works.**
- **C. Rebuild under a probe ref and re-tag when the digest is unchanged.** Instrument (live, real store): the SAME artifact built under a caller tag `probe-c-1`, then under `probe-c-2`, then the store's own index read back:
  ```
  build --tag probe-c-1: testbase -> ghcr.io/opencharly/testbase:probe-c-1 (built; image sha256:7e4752f4...)
  build --tag probe-c-2: testbase -> ghcr.io/opencharly/testbase:probe-c-2 (built; image sha256:7e4752f4...)
  store entries naming testbase:
    ('ghcr.io/opencharly/testbase:probe-c-2', ...)          <- present
    (no entry for probe-c-1)                                <- evicted
  ```
  The store keeps one entry per payload digest, so saving the same artifact under a second ref REPLACES the first: the probe consumes the very ref it intends to keep. **Eliminated by measurement, not by argument** — B needs no probe.

**Defects the spike found and this PR fixes:**
1. `LocalImageInfo.ID` is bare hex while `buildkitdrive.ImageID` returns `sha256:…`; the first implementation compared them raw and never matched (fixed by `sameDigest`, pinned by a test).
2. `plugin-box` always sends a computed CalVer in `BuildRequest.Tag`, so "an explicit `--tag`" was indistinguishable from the drive's auto tag. The decision now uses the TAG GRAMMAR (a bare `YYYY.DDD.HHMM[-N]` is the drive's own; every other tag is the caller's) and `buildImage` takes an explicit reuse policy so direct callers keep their ref.
3. The same-minute collision above (fixed by `mintAutoRef`).

**Winner:** B. **RCA verdict:** confirmed — B reuses the ref on the live path, and the pre-change red is reproduced.

## Change classification

A local build whose artifact is unchanged now keeps its existing ref instead of minting a new one; a changed artifact rebuilt inside one CalVer minute gets `-2`/`-3` instead of overwriting; push targets, mirrored builds, caller-tagged builds and direct callers are unchanged. **Breaking change + rollback:** none — the ref policy is internal to the drive; rollback is a revert of this squash.
